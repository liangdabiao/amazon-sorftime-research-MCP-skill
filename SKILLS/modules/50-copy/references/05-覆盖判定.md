# 05 · 覆盖判定

> 覆盖率的地位：**报数，不评分**。它只决定"哪些词漏了、漏得要不要命"，不决定文案好坏。
> 这一层的取向来自用户埋词 SOP 的 P7：`Reconsider uncovered keywords individually rather than forcing 100% coverage`。

---

## 一、三档判定

| 检查 | 条件 | 判定 | 处置 |
|---|---|---|---|
| **O1** | P0 词未覆盖 | **FAIL** | 必须补词或改文案，否则不许交 |
| **O2** | P1 词未覆盖 | **WARN** | 可以放弃，但必须在 `copy.json` 的 `coverage_reasons` 写理由 |
| **O3** | P2 词 | 只报数 | 不判定，不进问题清单 |

依据：上游 `prompts/master-prompt.md:122-126` 只对 P0 要求"列出已覆盖/未覆盖"，P1 只要求"覆盖情况"，P2 不管。**上游本来就是三档，不是我们新增的门槛。**

不参与覆盖检查的 prio：`BRAND` / `NEG` / `OBSERVE` / `NODATA`（见配置 `coverage.ignore_prio`）。品牌词、否定词、观察词、无数据词都不该进前台，漏了是正确行为。

---

## 二、匹配口径：词干，不是精确匹配

`coverage.match: stem`。一个词算覆盖，需要满足：

1. 该词的所有实义 token 都能在文案中找到**词干相同**的形式
2. 允许词序与前面的介词变化（`sink sponge holder` ≡ `sponge holder for sink`）
3. 允许单复数（`cup` ≡ `cups`）
4. 拆开分置两句**算覆盖**，但在清单里标 `SPLIT`

第 4 条的依据是用户 SOP 的 P5 + P6：允许语法调整、允许同簇合句。

词干化的简化规则（不引入 nltk，避免依赖）：

- 去尾部 `s` / `es` / `ies` → `y`
- 去尾部 `ing`（长度 >5 时）
- 全部小写，去标点

够用，且不会把 `glass` 误伤成 `gla`（`ss` 结尾不动）。

## 三、未覆盖词清单的字段

产物：`CP-03-覆盖清单.csv`

| 列 | 说明 |
|---|---|
| `keyword` | 词原文 |
| `prio` | P0 / P1 / P2 |
| `W` | 搜索量，来自词库 |
| `covered` | 是 / 否 |
| `where` | 命中在哪个字段（`title` / `bullets[2]` / `description` …） |
| `form` | `EXACT` 整短语命中 / `STEM` 词干命中 / `SPLIT` 拆词命中 |
| `layer` | 未覆盖时归因到哪一层（L0 / L1 / L2，见下） |
| `reason` | 放弃理由，从 `copy.json` 的 `coverage_reasons` 取 |
| `verdict` | PASS / FAIL（P0 未覆盖）/ WARN（P1 未覆盖） |

## 四、放弃理由必须归因到层

`copy.json` 里这样写：

```json
"coverage_reasons": {
  "kitchen sink organizer": "L2 重复：标题已含 sponge holder for kitchen sink，同词根叠加超上限",
  "bathroom sink accessories": "L1 表达：R=0.55，塞进第 5 点会让场景句读成凑数"
}
```

理由只有三种合法开头，对应 `02-埋词原则.md` 的三层：

| 前缀 | 含义 | 例子 |
|---|---|---|
| `L0 事实` | 事实卡不支持，或与本品冲突 | 「事实卡无皂位，soap 类词全禁」 |
| `L1 表达` | 塞进去会破坏可读性或事实准确性 | 「塞入会让第 3 点变成名词堆」 |
| `L2 重复` | 与已用词重复，或超词根上限 | 「与标题同词根，超 3 次上限」 |

**写不出归因的理由不算理由**，`check_copy.py` 会判 WARN 并要求补。这一条是为了防"懒得写就说读不通"。

## 五、`copy.json` 的完整 schema

```json
{
  "category": "sponge-holder",
  "generated_at": "2026-11-16",
  "selected_sp": "00-选定卖点.json",
  "title": "",
  "highlights": "",
  "bullets": ["", "", "", "", ""],
  "description": "",
  "search_terms": "",
  "coverage_reasons": {},
  "notes": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `category` | 是 | 对应 `调研/{category}/` 目录，也用于取品类禁写表 |
| `title` | 是 | 纯文本，不含标签 |
| `highlights` | 是 | 逗号分隔短语 |
| `bullets` | 是 | 恰好 5 条，顺序即位次 |
| `description` | 否（大纲外可选字段，默认不写） | 纯文本，空行分段，零 HTML |
| `search_terms` | 是 | 小写、空格分隔，≤250 字节 |
| `coverage_reasons` | 否 | P1 未覆盖词的归因，缺了对应词判 WARN |
| `notes` | 否 | 留给人工说明，脚本不读 |

## 六、覆盖率的正确用法

1. **只看 P0 是否全过**。P0 是 3 个词（sponge-holder 实例），漏一个就是明确缺口。
2. **P1 覆盖率报数，不设目标**。232 词里 P1 有 27 个，五点只有 5 条，物理上装不下 27 个词。
3. **不要用覆盖率排序文案版本**。这会把"堆词多的版本"选成最优，正好是官方明令禁止的方向。
4. **覆盖率高低与评分无关**。评分走 `amazon-listing-doctor` 的 CDQ 权重，本模块不产出分数。
