# 07 · 规则总表（埋词 / 格式 / 计分）

> 这份表回答三个问题：**每个字段写什么、写多少、凭什么这么选。**
> 每条规则都标来源等级，别把经验当官方：
> **[官]** 亚马逊官方文档写明 · **[经]** 行业实践或上游项目经验，无官方背书 · **[自]** 本项目自定，可调

## 〇、字段受众：谁写给谁看（2026-11-17 大方向）

前台展示逻辑变了，同一份 listing 现在有**两个读者**。写作标准按读者分，不再统一按"读起来顺"：

| 字段 | 读者 | 写作目标 | 失败形态 |
|---|---|---|---|
| 标题 | **人**（扫一眼做决策） | 一眼看懂是什么，同时搜得到 | 词堆成一串，人读不懂 |
| 亮点 | **人，尤其移动端** | 前几个词就说清"凭什么买你" | 开头写通用属性，差异化被埋在后面 |
| 五点 | **AI**（Top highlights / 导购抽取） | 每条都能被切成独立的事实句 | 空话、代词指代、只有形容词 |
| 描述 | 人（少量）+ AI | 补细节、补场景 | 堆词、用 HTML |
| ST | 纯机器 | 补索引 | 写成给人看的句子 |

**底层原因**：五点不再只靠人逐条读。AI 会从标题、五点靠前内容、页面里抽句子，放到五点上方展示。**抽不到，等于这条没写。**

由此两条铁律：

1. **五点的成功标准从"人读了舒服"变成"AI 抽得出"**
2. **亮点的成功标准从"信息写全"变成"前几个词够不够抓人"**

这两条会改变具体写法，见 §三、§四。

## 一、三套分数：先算清"什么值钱"

写文案涉及三套独立的分数，用途不同，不能混用。

### 1.1 词的价值 W —— 决定这个词排第几

```
W = 月搜索量 × R                   [自] 口径定义，见 skills/scripts/config.yaml
R = 0.5×R1 + 0.3×R2 + 0.2×R3       [自] 三项权重之和必须为 1
    任一 R1 或 R2 = 0 → R 直接判 0（一票否决）
```

| 维度 | 含义 | 取值 |
|---|---|---|
| **R1 本品相关性** | 搜这个词的人是不是在找这个东西 | 1.0 正常 / **0.5 邻类词** / 0 否定词 |
| **R2 形态匹配** | 安装形态对不对（本品是壁挂吸盘） | 1.0 壁挂精准 / 0.5 泛词 / **0 台面款或材质冲突** |
| **R3 竞品标题覆盖率** | 30 条竞品标题里有几条写了它 | 出现在 60% 竞品标题即满分，再多不加价 |

**为什么要乘 R 而不是直接用搜索量**：`kitchen sink` 月搜极可能上百万，但搜它的人不是找海绵架，写进标题只是白占字符。乘完 R 之后，`faucet rack` 这类词（R1=0）价值归零。

**优先级分档**（`prio`）：按 W 降序，**前 3 个进 P0，之后 27 个进 P1，其余 P2**；R 判 0 的进 NEG 否定清单。

> 竞争度（点击集中度 / SPR / 标题密度 / 商品数）**不进 W**。它决定"这个词怎么打"，不决定"先打谁"。这是 2026-11-16 的口径，别把两者混算。

**本品实例**：

| 词 | 月搜索量 | R | W | 落档 |
|---|---|---|---|---|
| sponge holder for kitchen sink | 167,620 | 1.0 | 167,620 | P0 第 1 |
| sink caddy | 125,363 | 1.0 | 125,363 | P0 第 2 |
| sponge holder | 94,716 | 1.0 | 94,716 | P0 第 3 |
| dish soap holder | 4,871 | 0.5 | 约 2,436 | P1（邻类，写文案时放弃） |

### 1.2 卖点的价值 M —— 决定哪条五点排前面

```
M = 0.45×S + 0.35×P + 0.20×D      [自] 沿用 amazon-listing-builder/reference/ranking-rules.md
G = P × (1 - cov)                  [自] 机会分：痛点很重但竞品都没解决
```

| 因子 | 含义 | 算法 |
|---|---|---|
| **S 需求强度** | 这个卖点关联的词有多大搜索量 | 卖点关联词搜索量之和 ÷ 全部卖点里的最大值（最大者为 1.0） |
| **P 痛点严重度** | 相关差评占比 | 差评占比 ≥30%→1.0；≥15%→0.7；≥5%→0.4；>0→0.2；0→0 |
| **D 差异化** | 本品有这个卖点的竞品有多少 | 按本品五点覆盖率 `cov` 四档：0→**1.00**；0-30%→0.70；30-60%→0.40；≥60%→**0.10** |

**D 为什么要反向**：人手一份的特性（cov≥60%）不是卖点，是入场券。只有本品独有（cov=0）才值 1.0 分。

**本品 5 条的实际得分**：

| 卖点 | S | P | D | M | 含义 |
|---|---|---|---|---|---|
| SP11 海绵+刷同放 | 1.00 | 0.2 | 0.1 | **54.0** | 需求最大，但人人都有（D 低） |
| SP03 双安装 | 0.024 | 0.4 | 0.4 | 23.1 | 需求小，痛点偏高 |
| SP13 两区分离 | 0.00 | 0.2 | 0.7 | 21.0 | 无搜索量，但差异化高 |
| SP10 PC 不锈 | 0.021 | 0.4 | 0.1 | 17.0 | 需求小且人人都有 |
| SP20 多场景 | 0.00 | 0.2 | 0.4 | 15.0 | 无搜索量 |

> 注意 SP13 和 SP20 的 S 是 0——它们的关联词没有搜索量。**M 低不代表不能写，代表它拉不动搜索流量，只能靠说服和防退价值占位**（见 `06-决断规则.md` 三种价值）。

### 1.3 文案覆盖率 —— 只报数，不评分

```
覆盖率 = 已覆盖词数 ÷ 可覆盖词数        [自]
匹配口径：词干（stem），允许词序变化、单复数、拆句        [自]
```

| 档 | 判定 | 处置 |
|---|---|---|
| P0 未覆盖 | **FAIL** | 必须改文案补上，不许交 |
| P1 未覆盖 | WARN | 可以放弃，但必须写归因（`L0 事实` / `L1 表达` / `L2 重复`） |
| P2 未覆盖 | 只报数 | 不判定 |

**覆盖率不设目标**：P1 有 27 个词而五点只有 5 条，物理上装不下。**更不能用覆盖率给文案版本排序**——那会把"堆词最多"的版本选成最优，正好是官方禁止的方向。

## 二、标题：75 字符，四段（第 3 段可选）

### 2.0 结构

```
品牌 + 核心品类词 +（同义变体）+ 差异属性 +（变体规格）
      └─ 必写 ──┘   └─ 有才写 ─┘   └─ 必写 ─┘    └ 有变体才写 ┘
```

| 段 | 装什么 | 本品 | 字符 | 为什么必须在这 |
|---|---|---|---|---|
| ① 品牌 | 固定写法，不翻译不改写 | Nieifi | 6 | 认人；官方建议放开头 |
| ② 核心品类词 | P0 里 W 最大的那个大类词 | Sponge Holder for Kitchen Sink | 30 | 决定能不能进这个类目的搜索结果 |
| ③ 同义变体（可选） | P0 里第二种主流叫法，新增 W ≥ 5,000 才写 | Sink Caddy | 10 | 多覆盖 12.5 万搜索量；**不是同义词堆砌**（见下） |
| ④ 差异属性 | R ≥ 0.6 的最强形态或功能差异 | with Suction Cups | 13 | 和几十个同款区分开，给点击理由 |
| ⑤ 变体规格（仅变体） | 尺码 / 件数 / 容量 | 无 | 0 | 本品单 SKU，此段不存在 |

**为什么不是把 75 字符写满**：

- 尺寸、颜色、数量官方禁（除非是变体维度），这条先砍掉一批候选词
- 剩下的词 W 都低于已用词，塞进去要挤掉更值钱的，是负收益
- 75 字符是**上界**，不是**配额**。写到 67 就停，是因为第 68 个字符换不到更多覆盖

**③ 和官方三段结构的关系**：官方 2026 推荐 `Brand + Core Product Type + Key Attribute`，这是**推荐结构，不是硬线**。标题的硬线只有两条——75 字符、不堆同义词密度。③ 带一个主流变体叫法在硬线之内：`caddy` 和 `holder` 是同一产品的两种叫法，买家搜的是两个词；官方禁的是 `sink sink sink` 这种同一个词反复堆。

### 格式 [官]

| 项 | 规则 |
|---|---|
| 字符上限 | **75 字符**（含空格） |
| 结构 | 品牌 + 核心品类词 +（同义变体）+ 差异属性 +（变体规格） |
| 允许 | 逗号、连字符、数字、首字母大写 |
| 禁止 | 全大写、促销语（Sale/Free shipping）、`™` `®`、卖家信息、竞品品牌、特殊符号 |
| **尺寸与颜色** | **不进标题**。规格槽专指变体规格（尺码/件数/容量），产品尺寸不是规格槽；本品单一 SKU，标题无规格位，尺寸只进五点或描述 |

> 官方禁项 12 条与判定方式见 `03-格式边界.md` §4.1，由 C12 拦截。

### 选词公式 [自]

```
进标题 = P0 全部 ∪（P1 按 W 降序填剩余名额）∩ R ≥ 0.6
```

各段取词范围：

| 段 | 从哪取 | 门槛 |
|---|---|---|
| ② 核心品类词 | P0 第 1 | 无条件 |
| ③ 同义变体 | P0 里另一主流叫法 | 新增 W ≥ `decisions.slot_min_w_gain`（5,000） |
| ④ 差异属性 | P1，或 P0 里的形态词 | R ≥ 0.6 |

双闸门必须同时过：只过 prio 不过 R，会把邻类词塞进来；只过 R 不过 prio，会把大量中长尾挤进 75 字符。

### 超长处理 [自]

```
第 1 步  共享词干压缩：复用已在标题的词干（holder / sponge / sink），不重写整词
第 2 步  压完仍超 → 从右往左删：先删场景，再删通用属性（本品无变体规格可删）
第 3 步  永不删：核心品类词、R ≥ 0.6 的差异属性
第 4 步  被删的 P0 词挪进亮点（官方确认亮点可被搜索索引，不要硬塞）[官]
```

### 权重影响 [官 + 经]

**标题与亮点等权**（2026-11-17 补）：官方答疑明确 `Item Name` 与 `Item Highlights` 都是搜索输入，两者**没有优先级差异**。所以标题装不下的 P0 词挪进亮点是**平移，不是降级**。原来这里写「亮点权重低于标题」是错的。

**没有任何官方字段权重表**。`标题 > 五点 > 描述 > ST` 是行业经验序，不是公式，别当精确权重用。也不能反过来用「标题权重高」当把词硬塞进 75 字符的理由。

**本品实例**：67 字符
`Nieifi Sponge Holder for Kitchen Sink, Sink Caddy with Suction Cups`
- 品牌 6 + 核心词 30 + 同义变体 10 + 属性 13
- 还剩 8 字符，没塞词——因为剩下的词 W 都低于已用词，塞进去要挤掉更值钱的

**为什么留 `Sink Caddy`**（2026-11-17 定，走收益门槛不是拍脑袋）：`sink caddy` 月搜 **125,363**，P0 第 2，远超 `slot_min_w_gain = 5000`。`caddy` 与 `holder` 是同一产品的两种主流叫法，不是同义词重复——官方禁的是 `sink sink sink` 这种密度堆砌，不是「用第二种叫法」。所以标题走四段：品牌 + 核心品类词 + 同义变体 + 差异属性。

> 官方 2026 推荐的「Brand + Core Product Type + Key Attribute」是**推荐结构，不是硬线**。标题的硬线只有两条：75 字符、不堆同义词密度。四段带一个主流变体叫法，在硬线之内。

## 三、亮点：125 字符，补标题没说的信息

### 3.0 结构：先过信息类目，再排顺序

亮点的官方定义是**标题的补充**——补材料、功能、使用场景、补充规格。所以它**不是「标题装不下的词的回收站」**：先把要说的信息列出来，词是副产品。

写法两步：**先平铺类目清单，再定顺序**。

| # | 信息类目 | 官方对应 | 本品能不能写 | 判定 |
|---|---|---|---|---|
| 1 | 差异化功能 | Core Feature | 两个分开的格子 | **必写**，排第 1 |
| 2 | 使用利益 | Benefit | 海绵和刷子不挨着 | **必写**，可与 1 合并成一个短语 |
| 3 | 安装方式 | Feature | 吸盘 / 背胶两种 | 标题没写全就必写 |
| 4 | 适用面边界 | Additional Spec | 能贴玻璃 / 瓷砖 / 不锈钢 | 有退货风险就必写 |
| 5 | 材料 | Material | 透明 PC 塑料 | 按门槛判 |
| 6 | 使用场景 | Use Case | 厨房水槽 / 浴室 / 房车 | 按门槛判 |

**第 5、6 类为什么不是必写**：它们过不了收益门槛。本品材质词（`sponge holder for kitchen sink plastic` 824 + `... clear` 504）合计 **1,328**；场景词（`rv kitchen essentials` 2,334 + `bathroom sink accessories` 1,967）合计 **4,301** 且 R 只有 0.55。都低于 `decisions.slot_min_w_gain = 5000`。

**不是没地方放，是按 SOP 判掉了**——这个理由要写进口径声明，不能默默不写。

**短语数量 3-5 个，总长 80-125 字符**。低于 80 说明信息量不够，超过 125 硬拦。

### 3.1 写法：短语，不是句子 [官]

官方示例 `100% Cotton, Highly Absorbent, Soft Texture, Kitchen and Bathroom Use`——四段全是名词短语或形容词短语，没有一段是「主语 + 谓语 + 宾语」。

```
对：two divided zones for sponge and brush, suction or adhesive mount, fits glass and tile
错：two divided zones keep sponge and brush apart
```

**为什么必须是短语**：125 字符里，短语能装 5 个信息点，句子只能装 3 个。补充信息是清单式的，不是叙述式的。

**唯一放宽**：第 1 个短语可以稍长（≤6 词），因为它是唯一会被单独看到的部分。但仍不写完整主谓句——`keep ... apart` 这种把利益写成谓语的，改成 `for sponge and brush` 这种带用途的名词短语。

### 3.2 顺序：第 1 个短语定生死，其余按「能打消多少疑虑」排

```
第 1 个 = 差异化，必须是具体名词（zones / hooks / divider），不能是形容词（large / premium）
第 2 个起 = 按疑虑强度排，不按搜索量排
```

**疑虑强度**（本品实测顺序）：能不能装上去 → 会不会掉 → 会不会坏 → 能不能换地方用。对应：安装方式 → 适用面 → 材料 → 场景。

**为什么不按搜索量排**：搜索量高的词已经进标题了（标题就是按 W 排的）。留在亮点里的词本来搜索量就低，按搜索量排等于按噪音排。

差异化取 `SP-01-卖点库_v2.csv` 的 `D` 列。本品排序：**两区分离 0.7 > 双安装 0.4 = 多场景 0.4 > 不锈 0.1 = 海绵+刷 0.1**。

### 3.3 索引：最后一步，不是第一步

```
定类目 → 写短语 → 看这些短语带了哪些词 → 只补标题漏掉且 R≥0.6 的词 → 补不进就不补
```

必须装的只有一种：**标题因 75 字符被删掉的 P0 词**（官方确认亮点可被索引，挪过来是平移不是降级）。

**重复标题的词 ≤2 个，且每个要过删除测试**：删掉它——句子仍成立、信息没少 → 凑索引，删；读不懂或信息缺失 → 表意必需，留。本品 `sponge` 属后者（`for sponge and brush` 删了就不知道给谁用）。

**不要为了装词改结构**。反例：为了让 `adhesive` 进亮点，把它从安装信息里拎出来单独做一个短语，三段变成「分区 / 背胶 / 尺寸」，读起来像参数表。

### 3.4 与五点的分工

| | 亮点 | 五点 |
|---|---|---|
| 回答什么 | 凭什么买你（**结论**） | 怎么做到、什么情况不行（**依据与边界**） |
| 写法 | 逗号分隔的短语 | 事实句，带数字 |
| 重复 | 整短语不得与五点相同 | —（五点之间也不允许） |
| 禁写 | 完整句子与句号、促销语与情绪词（premium / best）、品牌名（标题已有） | — |

### 3.5 本品成品拆解

`two divided zones for sponge and brush, suction or adhesive mount, fits glass, tile and steel`
= **95 字符**

| 短语 | 字符 | 承担类目 | 为什么在这 |
|---|---|---|---|
| `two divided zones for sponge and brush` | 39 | 差异化 ① + 利益 ② 合并 | D 最高 0.7；前 40 字符露出的就是「两个分开的格子」 |
| `suction or adhesive mount` | 26 | 安装 ③ | 标题只写了 suction；`adhesive` 是另一种装法，也是「我家墙能贴吗」的答案 |
| `fits glass, tile and steel` | 26 | 边界 ④ | 最大差评是吸盘脱落，先说清能贴什么 |

材料（⑤）与场景（⑥）没写，理由见 3.0 的门槛判定：1,328 与 4,301，都低于 5,000。

0 个情绪词，0 个整短语与五点重复，0 个完整主谓句。

### 3.6 权重影响 [官 + 经]

亮点与标题**同一档搜索输入**，官方答疑明说两者无优先级差异。它的性价比在「**多出 125 字符的索引位，不占标题预算**」。

但装词仍是次要任务、抓人是主要任务——原因不是权重低，是**展示位只有开头那几十个字符**。权重相同，注意力不同。

### 3.7 旧写法为什么不行

`adhesive strip mount, two divided zones, clear PC body, bathroom and RV use`

开头是 `adhesive`——通用安装属性，移动端露出这 20 个字符等于没说差异化。它是**按装词逻辑排的，不是按展示逻辑排的**。

还有一版更差：`two divided zones keep sponge and brush apart, suction or adhesive mount, fits glass, tile and steel`（100 字符）。信息没错，但第 1 段是完整主谓句，不符合「逗号分隔的短语」；而且把利益写成谓语，占掉 15 个字符，同样的信息用 `for sponge and brush` 6 个词就够。

## 四、五点：5 条 × 最多 500 字符

### 4.1 字符三档 [官 + 自]

| 判定 | 阈值 | 性质 |
|---|---|---|
| FAIL | **> 500 字符** | [官] `500 characters maximum (can vary by product category)` |
| WARN | 256-500 | [自] 255 是本项目自定的保守线，**不是官方数** |
| PASS | 150-255 | [自] 目标区间，移动端每条只露前 70-80 字符 |
| WARN | < 150 | [自] 信息量不足 |

### 4.2 句式五条 [官]

来源：`sellercentral.amazon.com/help/hub/reference/external/GX5L8BF8GLMML6CX`

| 规则 | 官方原文 |
|---|---|
| 冒号开头 | `Add a header with a colon followed by a description` |
| 分号分隔短语 | `Use semicolons to separate phrases within a single bullet point` |
| 句末不加标点 | `Format as a sentence fragment, and don't use end punctuation` |
| 首字母大写 | `Begin with a capital letter` |
| 每条讲不同信息 | `Each bullet point must mention unique product information` |

```
对：Holds tight on smooth sinks: dual suction cup and adhesive strip; fits tile, glass and stainless steel
错：Holds Tight on Smooth Sinks — Dual suction cup... keep it in place. Fits tile...
```

**为什么格式必须服从**：官方明写重复内容会被移除、格式不合规会被改写。这是上架风险，不是审美问题。

### 4.3 每条的信息密度 [自，2026-11-17 新增]

亚马逊前台已有 AI 导购与 Top highlights，会把标题、五点靠前内容和页面里**易抽取的句子**提到五点上方展示。

```
每条必须含 ≥ 1 个事实锚点，四类之一：
① 数字     8.5 x 3.3 in / 2 suction cups / 2 zones
② 材质工艺 PC / anti-rust / clear plastic
③ 结构     open frame / 2 hooks
④ 边界     fits glass, tile and stainless steel / not for wood or frosted surfaces
整条只有形容词（sturdy / premium / easy to use）→ FAIL
```

**判定标准是"能不能被单独摘出来当一句话用"**：抽到 `sturdy and convenient` 等于没抽，抽到 `2 divided zones keep sponge and brush apart` 才有用。

**AI 可读性六条**（写给机器抽，不是写给人读）：

| # | 规则 | 反面例子 |
|---|---|---|
| 1 | **每条自成一个知识块**：主张 + 依据 + 边界，脱离上下文也能读懂 | 靠上一条的 `this` / `it` 指代 |
| 2 | **不用代词**：`it` / `this` / `they` 换成具体名词 | 被单独摘出来时没有前文，指代变空 |
| 3 | **实体密度**：每条 ≥ 2 个实体（名词 / 数字 / 材质 / 尺寸） | 全条只有 `sturdy and convenient` |
| 4 | **结论前置**：开头 5-8 词就说清这条讲什么 | 先铺垫场景，最后才说结论 |
| 5 | **不堆情绪词**：`premium` / `amazing` / `you'll love` 对抽取零贡献还占字符 | 形容词占掉半个句子 |
| 6 | **关键词自然嵌入**：AI 能识别语义，硬塞会让句子断裂、降低可信度 | `sink caddy organizer rack holder` 连成一串 |

**与人读的区别**：人需要过渡、语气、节奏；AI 需要实体、边界、结论。五点按后者写，读起来会偏"干"，**这是有意的**——干但可抽取，好过顺但抽不出东西。

配套三条位置要求：

1. **每条主语明确**，不靠上一条的指代（会被单独摘出来）
2. **关键卖点不放第 5 条**，也不指望 A+ 兜底
3. 防退句挂到最相关那条末尾，**不单独占一个位置**

### 4.4 五点排序：按 M 降序 [自，2026-11-17 定]

```
按 M 降序（M 高 = 需求大或痛点重）
防退句不单独占位，挂最相关那条末尾
```

**为什么不再用手选顺序**：五点是写给 AI 抽的，人的主观排序（"先讲最强差异"）对机器没有意义。M 已经把需求和痛点算进去了，用它排是唯一有依据的顺序。

### 4.5 重复阈值 [自]

| 项 | 全篇上限 | 跨五点上限 | 理由 |
|---|---|---|---|
| 同一整短语 | 3 次 | 1 条 | 整短语重复才叫堆词 |

### 4.6 选词逻辑 [自]

```
每条五点 = 该卖点的支撑词 ∩（R ≥ 0.6）∩（不与前几条重复超阈值）
算收益：本行新增覆盖词的 W 加总
  ≥ 5,000  → 写
  < 5,000  → 仅当兼有说服/防退价值才写，否则删
```

`kitchen sink organizer` 月搜 92,519，另带 8 个词，远超 5,000 → 自动写 `organizer` 和 `rack`。

## 七、优先级总则

```
格式硬线   >  事实准确  >  可读性  >  覆盖率
[官]         [自 L0]      [自 L1]    [自 L2]
```

1. **格式不合规会被改写或下架**，优先级最高
2. **事实不能编**：数值、材质、承重，事实卡没有的一律不写
3. **可读性压过覆盖率**：为埋词改坏句子，删词不改句
4. **覆盖率是目标不是尺度**：不追 100%，不为它牺牲上面三条
