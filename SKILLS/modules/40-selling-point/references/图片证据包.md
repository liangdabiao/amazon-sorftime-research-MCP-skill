# 图片证据包格式

图片维度是这个模块唯一需要人工喂数据的部分。原因是硬边界，不是方法问题：

- 沙箱无外网，`curl https://m.media-amazon.com/...` 直接 SSL 断
- `web_fetch` 打 `amazon.com/dp/<ASIN>` 返回 Access restricted 拦截页
- `asin_detail` 只返回一张主图 URL（`imageUrl` / `zoomImageUrl`），没有 7 图列表，图片本身也读不了

所以要买主图/场景图截图，按下面的格式放好。

## 一、目录结构

```
selling-point/image_pack/
├── manifest.csv
├── B0CKZ4VDT1/
│   ├── 01.jpg
│   ├── 02.jpg
│   ├── ...
│   └── 07.jpg
└── B0H8NV58N6/
    └── ...
```

- 一个 ASIN 一个文件夹，文件夹名就是 ASIN（大写，10 位）
- 文件名 `<两位位次>.jpg`，从 `01` 到 `07`
- 缺图就空着，不要拿别的图顶替——缺位比错位好

## 二、manifest.csv

| 列 | 说明 |
|---|---|
| `asin` | 10 位 ASIN |
| `pos` | 1-7 |
| `slot` | 主图 / 卖点图 / 场景图 / 细节图 / 尺寸图 / 安装图 / 对比图 |
| `file` | 相对路径，如 `B0CKZ4VDT1/01.jpg` |
| `captured_at` | 截图日期 `YYYY-MM-DD` |
| `note` | 这张图实际在讲什么（一句话，可选） |

## 三、7 个图位的定义

| 位次 | 名称 | 任务 | 典型画面 |
|---|---|---|---|
| 1 | 主图 | 点击 | 纯白底、产品占比 ≥85%、无文字无道具 |
| 2 | 卖点图 | 差异化 | 一句话主张 + 对应结构特写 |
| 3 | 场景图 | 对号入座 | 真实水槽、有海绵/刷子/皂液 |
| 4 | 细节图 | 材质做工 | 卡扣、焊点、边缘、厚度 |
| 5 | 尺寸图 | 降退货 | 长宽高标注、与常见物对比 |
| 6 | 安装图 | 降顾虑 | 拆解步骤、适用面示意 |
| 7 | 对比图 | 转化 | 与旧款/竞品的差异，或前后效果 |

位次定义写在 `sp_config.yaml` 的 `image.slots` 里，改这里才生效。

## 四、每张图要记什么

读图时按六项记录，缺项就写"未见"：

1. **画面构成**：主体、道具、人物、文字量（无 / 少量标签 / 大段文案）
2. **卖的什么**：这张图在讲哪个卖点，映射到 `sp_defs` 的 `sp_id`；讲不清的记空
3. **视觉证据类型**：尺寸对比 / 使用场景 / 材质特写 / 结构标注 / 安装步骤 / 痛点对比 / 信任背书
4. **信息密度**：图里出现了几个数字、几个英文词
5. **合规**：主图是否白底、产品占比、有无文字/logo/边框/价格（对照 `_common/政策边界.md`）
6. **位次**：这张图排第几（主图第 1 位的权重远高于第 7 位）

## 五、汇总成什么

`SP-03` 之外再出一张 `ASIN × 图位 × 卖点` 的矩阵，回答三件事：

- 哪些卖点是**必上图**的（多数竞品都在图 2-4 讲同一件事）
- 哪些卖点**只有文案没有图**（文案写了但没人上图，说明可信度存疑）
- 哪些图位是**空着的**（7 个位次里没人用的，是差异化空间）

结果回填到 `SP-04`，把"应承载图位"换成实际观察，并给每个卖点补上第三维证据。

## 六、怎么启用

1. 图包放好、manifest 写完
2. 改 `skills/scripts/sp_config.yaml`：`image.enabled: true`
3. 重跑 `python skills/scripts/build_selling_points.py`
4. 重跑 `python skills/scripts/check_sp.py`

启用后 `证据维度` 会从最多 2 变成最多 3，A 级门槛不变（≥2），但单源占比会下降，部分 C 级待验证卖点会往上走。

## 七、截图口径

同一类目所有竞品用同一套截法：桌面端、同一缩放、关掉个性化推荐、只截图片区不含评论区。截图日期写进 manifest，因为主图会换。

不要用 A+ 图冒充 7 图位——A+ 属于详情页下半部分，是另一套逻辑（另建 `aplus/` 目录，回填到 `SP-04` 的备注列）。
