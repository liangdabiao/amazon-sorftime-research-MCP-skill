# 06 · 自动决断规则（什么时候不用问人）

> **这份文件解决的问题**：写文案时会遇到几十个「这个词放不放」「这条留不留」的小选择。
> 如果每个都要回来问用户，一个 listing 要问二十次，项目跑不动。
> 下面三条规则把这些选择变成可计算的判断，**能算的一律自己算，算不了的才问，并说清为什么算不了**。

---

## 一、底层：一个位置只有三种价值

写文案占的是稀缺位置（标题 75 字符、亮点 125 字符、五点 5 条、描述 7 段）。
**每一个位置都必须换来至少一样东西，否则就是浪费。** 能换来的东西只有三种：

| 价值 | 含义 | 怎么算 | 谁提供 |
|---|---|---|---|
| **① 覆盖价值** | 加了这个词，多几个买家搜索词能搜到你 | 可精确算：本行新增覆盖的搜索词，把它们每月的搜索量加起来 | `keyword_library.csv` 的 `W` 列 |
| **② 说服价值** | 让买家相信这条卖点是真的、值得买 | 不可算，靠卖点库的 M 分排序决定谁排前面 | `SP-01-卖点库_v2.csv` 的 `M` |
| **③ 防退价值** | 提前说清「什么情况不适合」，减少退货和差评 | 看事实卡有没有写限制 | `00-事实卡.json` 的 `limits` / `surfaces.not_ok` |

**决策顺序固定**：先算 ①，再查 ②③。**三种价值全为零的位置，必须删掉或换内容。**

这条底层规则推翻了「读着顺就留着」——读得顺不是价值，只是没犯错。

---

## 二、判定 1：一个词要不要写进去

### 算法

对每个候选词，按顺序过三关：

```
第 1 关  事实层：写它会不会改变这条五点的核心意思，或说出事实卡没有的事？
         → 会，放弃。写进归因（L0）。
第 2 关  口语层：硬塞进去会不会把句子写拧、让母语者觉得奇怪？
         → 会，放弃。写进归因（L1）。
第 3 关  算收益：本行新增覆盖的搜索词，把 W 加总 = 这个词值多少搜索量
         → ≥ slot_min_w_gain（默认 5000）→ 写
         → < 阈值 → 只有当它同时承担说服或防退价值时才写（作人话），否则删
```

### 为什么用「搜索量之和」而不是「覆盖了几个词」

覆盖 9 个每月只搜 10 次的词，等于 90 次曝光；覆盖 1 个每月搜 9 万次的词，等于 9 万次。
**数量不等于价值，加总才是。** 这也解释了为什么不追 100% 覆盖率——尾部词加起来可能还不如一个头部词。

### 本品实例（sponge-holder）

**疑问：五点第 3 条讲「两个分区」，要不要塞 `organizer`？**

| 走的步骤 | 结果 |
|---|---|
| 第 1 关 事实层 | 事实卡写了 `structure.zones = 2`，`open_frame = true`。这条本来就在讲「分格收纳」，写 organizer 不改变意思 → 通过 |
| 第 2 关 口语层 | `a kitchen sink organizer rack with a slot for the sponge` 是正常英文 → 通过 |
| 第 3 关 算收益 | `kitchen sink organizer` 月搜 **92,519**，另带 8 个词，合计远超 5000 → **写** |

**结论：自动写，不需要问。** 上一版判「位 3 零词」是用「有没有 divided 这个词」当标准，问错了问题——该问的是「这条讲的事，买家会用什么词搜」。

**反例（同一个产品，另一个词）**：`dish soap holder`（月搜 4,871）。事实卡没有任何皂盒结构。
第 1 关就不通过 → 放弃，归因写 `L0 无皂位事实`。这个也不需要问。

## 三、判定 2：零覆盖的那一条留不留

### 算法

五点是 5 个宝贵位置。每一条必须至少拿到 ② 或 ③ 中的一样：

```
覆盖价值 > 0                        → 留
覆盖价值 = 0，但有防退句或事实规格   → 留（作用是不退货，不是拉流量）
覆盖价值 = 0，且没有防退句、没有规格 → 删掉，把位置让给下一条卖点
```

**不允许的理由**：「读着顺」「画面感好」「凑满五条」。

### 本品实例

**疑问：五点第 5 条讲「厨房、浴室、房车、洗衣房都能用」，一个搜索词都带不来，留不留？**

先看它还装了什么：

| 内容 | 价值类型 |
|---|---|
| `not for wood, frosted or textured surfaces` | ③ 防退——买家买回去贴不住是最主要的差评来源（事实卡写明 `top_complaint_risk = 吸盘脱落`） |
| `bathroom / RV / laundry` 场景 | ② 说服——让买家想到自己家的使用场景 |

**结论：留。** 它不是靠「画面感」留下来的，是靠那句「不适合木面和磨砂面」。
如果这条只写了三个场景、没写限制，按规则就该删——现在它不该删。

**这条规则同时给出了写法要求**：五条里必须有一条承担防退。如果定稿卖点里没有，就把防退句挂到最相关那条的末尾，不单独占位。

## 四、判定 3：亮点写什么、第一句写什么

### 底层

亮点的读者是**人，而且多半在手机上**。移动端展示位窄，只露开头一小段，**开头写通用属性，等于把差异化藏起来**。

所以亮点有两条独立规则，不要混成一条：

```
【必备】三类词缺一不合格：差异化核心名词 / 索引补位词 / 边界或适用面（见 07 §3.0）
【位置】第 1 个短语 = 差异化最强的特性（SP-01 卖点库 D 列最高）
【装词】第 2 个起 = 标题被砍的 P0 词 → 未覆盖的 P1 词 → 通用规格
                  重复标题的词 ≤ 2 个（highlight_repeat_max），且每个须过删除测试
```

**为什么不是"先装词再考虑可读"**：125 字符里，词装得再满，如果前 20 个字符是 `adhesive strip mount` 这种谁都有的话，人不会往下看。**先解决被不被看到，再解决搜不搜得到。**

### 本品实例

| 项 | 值 |
|---|---|
| 标题 | `Nieifi Sponge Holder for Kitchen Sink, Sink Caddy with Suction Cups`（67 字符，没砍词） |
| D 最高卖点 | **两区分离 D=0.7**（其次双安装 0.4、多场景 0.4） |
| 第 1 个短语 | `two divided zones keep sponge and brush apart` |
| 后面装词 | `suction or adhesive mount`（补 `adhesive`）、`fits glass, tile and steel`（补适用面） |
| 重复词 | 0 个（标题没砍词，无需补） |

旧写法 `adhesive strip mount, two divided zones, ...` 把通用安装方式放第一，是**按装词逻辑排的，不是按展示逻辑排的**。

**什么情况下会允许重复**：标题超 75 必须砍掉 `caddy` 时，`caddy` 就得进亮点——这时候重复是必须的，不重复才叫丢词。但**它仍然不占第一位**，第一位留给差异化。

## 五、只有三种情况需要问人

规则能算的一律自己算。以下三类规则算不了，必须回来问，**且要说明为什么算不了**：

| 类型 | 例子 | 为什么规则算不了 |
|---|---|---|
| **事实缺失** | 吸盘材质没填，要不要写 `silicone` | 规则不能编造事实，只能绕开或补数据 |
| **商业取舍** | 5 条卖点选哪 5 条、价格带怎么打 | 涉及成本、库存、竞争策略，数据里没有 |
| **品牌调性** | 语气偏专业还是偏亲切、要不要提「比竞品更牢」 | 是品牌资产判断，不是逻辑判断 |

**不属于这三类的，一律不要问。** 包括：某个词放第几条、某条写多长、亮点写几个词、ST 要不要留某个低频词——这些全在本文和 `02-埋词原则.md` 的规则里。

## 六、每次跑完必须报的「自动决断清单」

交付时列一张表，让用户能事后抽查，而不是事前被问：

| 决断 | 依据 | 结果 |
|---|---|---|
| 五点第 3 条埋 `organizer` | 新增覆盖 9 词，含月搜 92,519 的 `kitchen sink organizer` | 写 |
| 放弃 `dish soap holder` | 事实卡无皂位结构（L0） | 不写 |
| 五点第 5 条保留 | 承担防退句「不适合木面/磨砂面」 | 留 |
| 亮点 0 重复词 | 标题未超 75 字符，无被砍的 P0 词 | 无重复 |

**用户看这张表就能判断规则跑得对不对，不需要在写之前替我做二十次选择。**
表里出现「依据」栏写不出规则编号的项，才是真的需要问人的项。
